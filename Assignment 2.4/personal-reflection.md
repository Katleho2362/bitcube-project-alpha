# Sprint 1 — Personal Reflection

## Key Learning

The biggest lesson I learned during Sprint 1 is that sprint work needs to be checked and managed continuously. Even when planning is done properly, blockers, unclear requirements, and testing problems can still affect progress during the sprint.

## Assumptions That Failed

The main assumption that failed during Sprint 1 was thinking that all requirements were fully clear before development started. During implementation, the equipment filtering requirements still needed more clarification, which slowed down progress.

## Behavioural Change

One thing I would improve in Sprint 2 is communicating and clarifying requirements earlier before starting implementation. This can help reduce delays and improve sprint progress.

## Professional Growth

To perform better in a real Scrum team, I still need to improve my communication, sprint monitoring, and requirement analysis skills. I also need to improve testing during development instead of leaving most testing until the end of the sprint.
